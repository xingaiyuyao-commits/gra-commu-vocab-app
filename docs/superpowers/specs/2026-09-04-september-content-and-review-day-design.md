# 9月最新版教材・復習日50問・編集画面廃止 設計

作成日: 2026-09-04
対象: ÖSH Vocabulary Challenge（Clacel / TOEIC / IELTS）

## 1. 目的

1. 本番サイトの問題内容を、ユーザー指定の最新版PDFへ全面更新する。
2. 7日サイクルの復習日に、直前6日間から各コース50問をバランスよく出題する。
3. 復習問題は、実際に参加者の誤答が多かった問題を優先する。
4. 不要になった単語リスト編集画面と、その書き換えAPIを廃止する。
5. 問題文やヒントから正答が分かる状態を自動検査で防止する。

## 2. 正本と対象範囲

教材内容の正本は次の3ファイルとする。

- `Clacel_9月範囲.pdf`
- `TOEIC_9月範囲.pdf`
- `IELTS_9月範囲.pdf`

PDFは2026年9月6日をDay 1とし、9月30日のDay 25までを収録している。復習日のDay 7・14・21は新規問題を持たない。

収録内容は次のとおり。

| コース | 新規学習日 | 問題数 |
|---|---:|---:|
| Clacel | 22日 | 420問 |
| TOEIC | 22日 | 440問 |
| IELTS | 22日 | 440問 |

ClacelはPDFどおり、Day 2が19問、Day 9が12問、Day 18が19問、Day 25が10問である。その他の収録日は20問とする。

PDFに含まれないDay 26・27・29・30は9月の問題選択肢から削除する。Day 28は2026年10月3日に当たり、直前のDay 26・27が今回のPDFにないため、この更新では追加しない。Day 28以降は次月教材を受領した時点で別途追加する。

体験会の各コース20問は通常日データとは分離し、現行内容を維持する。

## 3. 教材データ構造

本番サーバーがPDFを直接解析する方式は採用しない。PDFから事前に抽出・検証したJSONをGitへ保存し、RailwayはそのJSONだけを読み込む。

教材データはコースごとに分け、各問題へ次の項目を持たせる。

```json
{
  "datasetRevision": "2026-09-04-<source-hash>",
  "course": "clacel",
  "day": 1,
  "questionId": "2026-09/clacel/day01/q15",
  "answer": "leave",
  "base": "leave",
  "hint": "l_____",
  "ja": "OをCのままにしておく、置き忘れる、去る",
  "sentence": "Try not to ___ anything in the taxi, you'll probably never see it again.",
  "sentenceJa": "タクシーには何も残さないようにしてください。おそらく二度と目にすることはないだろうから。"
}
```

`datasetRevision`を結果記録にも保存し、将来同じDay・設問番号の内容が変更されても、別版の誤答を混ぜない。

取り込み処理はPDFのファイル名・SHA-256・日別問題数を記録する。教材更新後は、日・設問番号・正答・例文・日本語訳の欠落と重複を検査してからJSONを確定する。

## 4. 正答漏えい防止

Clacel Day 1の`leave`は、PDFの日本語欄にある`(leave O C)`が正答を露出している。サイト用データでは、ユーザー承認済みの次の表現へ変更する。

> OをCのままにしておく、置き忘れる、去る

全問題について、次を自動検査する。

- `sentence`には空欄`___`が1つ以上ある。
- 空欄を除いた英文に、正答または見出し語が独立した英単語として残っていない。
- 日本語ヒントに正答の英字表記が残っていない。
- 正答、見出し語、例文、日本語訳が空でない。
- 同じDay内で`questionId`が重複していない。

検査に失敗した教材は本番へ反映しない。

## 5. 通常日の結果保存

結果発表が確定した時点で、既存の`/data`ボリュームへ日付・コース単位の記録を保存する。

```json
{
  "date": "2026-09-06",
  "category": "clacel",
  "datasetRevision": "2026-09-04-<source-hash>",
  "day": 1,
  "participantCount": 100,
  "perfectNames": ["Kaho"],
  "questionStats": [
    {
      "questionId": "2026-09/clacel/day01/q15",
      "attempts": 100,
      "wrongCount": 28,
      "reasonCounts": {
        "spelling": 12,
        "inflection": 7,
        "blank": 5,
        "other": 4
      }
    }
  ]
}
```

個人の回答文字列は長期保存しない。問題ごとの集計値だけを保存するため、100人規模でも保存量は小さい。

現在の結果画面用「誤答上位3問」は`questionStats`から生成する。保存自体は上位3問に切り詰めず、その日に出題した全問題を保持する。

同じ日・同じコースの結果は同じキーへ保存する。誤って結果確定処理が再実行されても加算せず置き換えるため、二重集計しない。週次集計は日次記録から都度組み立てる。

## 6. 復習日50問の選定

各コースを独立して選定する。Day 7はDay 1〜6、Day 14はDay 8〜13、Day 21はDay 15〜20を対象にする。

### 6.1 日別配分

1. 6日から8問ずつ選び、48問を確保する。
2. 6日間のうち平均誤答率が高い2日へ1問ずつ追加する。
3. 最終配分は4日が8問、2日が9問となる。

平均誤答率は、その日の`wrongCount`合計を`attempts`合計で割って求める。結果記録がない日は0として扱い、同率の場合はランダムに決める。

### 6.2 各日の問題選定

1. `wrongCount`が1以上の問題を、誤答人数の多い順に選ぶ。
2. 誤答人数が同じ場合は誤答率の高い問題を優先する。
3. それでも同じ場合はランダムに決める。
4. 誤答問題だけでその日の8〜9問を満たせない場合のみ、未選択問題からランダムに補う。

この順序により、各日のバランスを保ちながら、利用可能な範囲で最大限多くの誤答問題を含める。

### 6.3 出題確定

- 50問を選んだ後、出題順をシャッフルする。
- 選定とシャッフルはホストが開始した時に一度だけ実行する。
- 同じルームの全参加者へ、同じ50問を同じ順番で配信する。
- 確定した50問と順番をルーム状態へ保存する。
- リロード、再接続、Railway再起動では再抽選しない。
- 通常日は20問・5分、復習日は50問・12分30秒とする。
- 制限時間0秒で自動提出し、再読み込みで終了時刻を延長しない。

## 7. データ不足時と異常時

- 直前6日間の結果が一部または全部なくても、教材データがあれば復習日は開催できる。
- 結果がない日では、その日の問題からランダム選出する。
- 対象6日から重複なしで50問を構成できない場合は開始せず、ホストへ不足理由を表示する。
- 教材データの形式検査に失敗した場合はサーバー起動またはデプロイ検査を失敗させる。
- `/data`への保存が必須の環境で保存できない場合は、問題選定を確定せず開始を止める。
- 保存済みルームの`datasetRevision`と現在の教材版が異なっても、進行中ルームは保存済み問題を優先して復元する。

## 8. 画面変更

ホストの問題セット選択に、通常日と同じ並びで復習日を表示する。

- `Day 7（復習50問）`
- `Day 14（復習50問）`
- `Day 21（復習50問）`

今回未収録のDay 26・27・28・29・30は表示しない。体験会は現行どおり独立した選択肢として残す。

参加者の問題画面、提出確認、結果発表後の復習機能は、問題数と制限時間への対応以外は現行動線を維持する。

## 9. 単語リスト編集機能の廃止

次を削除する。

- `public/admin-words.html`
- `/api/admin/wordtests/:category`のGET・POST
- `ADMIN_PASSWORD`を使う教材編集用認証
- 教材JavaScriptをサーバーから書き換える直列化処理
- 編集画面・編集API専用テスト

結果履歴用の`RESULTS_ADMIN_PASSWORD`は別機能なので維持する。

廃止後の教材更新経路は次に一本化する。

1. 最新PDFを受領する。
2. ローカルの取り込み処理でJSONを生成する。
3. 自動検査を通す。
4. GitHubへコミット・プルリクエストを作成する。
5. CI成功後にmainへマージする。
6. Railwayがmainの確定コミットをデプロイする。
7. 本番URLで通常日・復習日・再接続を確認する。

## 10. テスト

### 教材検査

- PDF由来のファイルハッシュと取り込み記録が一致する。
- 対象Dayが`1〜6, 8〜13, 15〜20, 22〜25`である。
- Clacel 420問、TOEIC 440問、IELTS 440問である。
- Dayごとの問題数、正答、順番がPDFと一致する。
- 必須項目の欠落、ID重複、正答漏えいが0件である。
- `leave`の日本語ヒントに`leave`が含まれない。

### 復習日検査

- 各コース50問、重複0件である。
- 6日すべてから8〜9問ずつ含まれる。
- 誤答人数が多い問題が同じ日の未誤答問題より優先される。
- 結果0日、一部欠損、全日欠損でもランダム補充できる。
- 50問未満の不正な教材では開始を拒否する。
- 同じルームの参加者へ同じ順番が届く。
- 再接続・プロセス再起動後も問題と終了時刻が変わらない。

### 廃止・回帰検査

- `admin-words.html`が配信されない。
- 教材編集APIが利用できない。
- 結果履歴APIと`RESULTS_ADMIN_PASSWORD`は従来どおり動作する。
- 通常日の20問・5分を維持する。
- 体験会の20問と満点者発表を維持する。
- ホスト1人・参加者99人で、通常日と復習日を負荷確認する。
