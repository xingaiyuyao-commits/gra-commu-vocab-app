# 運営用共有パスワード・結果後復習導線 改修設計

## 目的

運営者約5人だけがルームを開催できるようにし、参加者はホストがルームを終了した後も、同じブラウザから期限内の復習を再開できるようにする。

## 確定事項

- 運営者認証は5人共通の共有パスワードを使う。
- パスワードは画面共有を始める前に入力し、認証状態を12時間保持する。
- 結果履歴用の`RESULTS_ADMIN_PASSWORD`とは分離し、新しい`OPERATOR_PASSWORD`を使う。
- 参加者の結果画面には「ルームを退出する」「ホームに戻る」のどちらも表示しない。
- 結果画面をその日の復習拠点とし、画面内で確認と解き直しを完結させる。
- サイトのドメインは毎日同じまま、参加コードと招待リンクは開催ごとに新しく発行する。
- 各日の結果を同じブラウザへ7日間保存し、同じ日の招待リンクから結果・復習を再開できるようにする。
- 公開ホームはZoomで共有する開始画面として維持する。
- ホームの開催ボタンは、事前ログイン済みの運営者のブラウザだけに表示する。
- 「ゲーム選択に戻る」は、単語チャレンジの画面では「ホームに戻る」に統一する。

## 運営者認証

### ログイン

運営者には事前ログイン専用URLを共有する。入力項目は共有パスワードだけとし、認証成功後は公開ホームへ戻す。

画面共有中の再入力を避けるため、認証状態は12時間有効とする。運営者はZoom開始前に専用URLからログインし、ホームへ戻ってから画面共有を開始する。

### ホームでの表示

- 未認証のブラウザでは、公開ホームに運営用リンクや開催ボタンを表示しない。
- 認証済みの運営者ブラウザでは、同じ公開ホームに「開催画面を開く」を表示する。
- 「開催画面を開く」はパスワードの再入力なしで開催画面へ進む。
- 認証状態の確認中はボタンを非表示のままにし、一瞬だけ一般参加者へ見える表示を防ぐ。
- 開催画面のURLを直接開いた未認証者にはログインを要求し、開催UIを表示しない。

### パスワードとセッション

- 共有パスワードはRailwayの`OPERATOR_PASSWORD`環境変数にだけ保存する。
- Git、HTML、JavaScript、`localStorage`、URLには保存しない。
- 認証成功時に、12時間有効な署名付きセッションCookieを発行する。
- Cookieには`HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`を指定する。
- ログアウト時はCookieを削除する。
- パスワード変更時は既存セッションが無効になる署名方式にする。
- 未設定時は認証を省略せず、運営用機能を利用不可にする。

### サーバー側の権限制限

画面の表示制御だけに頼らず、次のSocket.IO操作をサーバー側で拒否する。

- ルーム作成
- 問題セット選択
- 回答開始
- 開催中止
- 結果発表
- ホストによるルーム終了
- ホストとしての再接続

参加者の招待リンク、回答、提出、個人復習には認証を要求しない。

### 不正試行への対応

- IP単位でログイン失敗を記録する。
- 15分以内に5回失敗した場合は一時的にログインを拒否する。
- エラー文ではパスワードの正誤以外の内部情報を返さない。
- パスワード、Cookie、認証リクエスト本文をログへ出力しない。

共有パスワードのため、1人だけを停止することはできない。運営者の離脱または漏えいが疑われる場合は、`OPERATOR_PASSWORD`を変更して5人全員へ再配布する。

## 開催単位と参加リンク

- 通常日、復習日を含め、開催ごとに新しい4文字の参加コードを発行する。
- 招待リンクにはその日の参加コードを含める。
- 同じ参加コードを複数日にわたって再利用しない。
- 終了後の招待リンクは新規参加用には使わず、そのブラウザに保存された当日の結果・復習を開くために使う。
- 翌日の新しい招待リンクでは、前日の保存結果に干渉せず、新しいルームへ参加する。

## 参加者の結果後導線

### 結果画面

- 「今回の間違いを今すぐ解き直す」は維持する。
- 参加者の「ルームを退出する」と「ホームに戻る」はどちらも表示しない。
- 結果確認と解き直しの往復は同じ結果画面内で完結させる。
- 終了後は参加者自身がブラウザの画面を閉じる。
- 結果発表を受信した時点で、再表示に必要な個人結果と復習データを端末へ保存する。
- 保存に成功した場合は「この結果と復習内容は、このブラウザに7日間保存されます」と表示する。
- ブラウザ設定などで保存できなかった場合は「この画面を閉じると結果を復元できません」と表示する。
- ホストには従来どおり「本日のルームを終了する」を表示する。

### 7日間の結果保存

新しい`oshQuizSavedResultsV1`を、ルームコードをキーにした端末内の結果保存に使う。

- 保存対象はルームコード、コース、問題セット名、結果日時、正解数、問題数、参加者自身の回答、正答・別解・意味・例文、結果画面に必要な発表内容とする。
- 参加者のルーム再接続用セッショントークンは保存結果へ複製しない。
- 各結果は結果日時から7日間保持し、期限切れを読込時に自動削除する。
- 1人が複数コースへ参加する場合も考慮し、3コース×7日分の最大21開催を保持する。上限を超えた場合は古い結果から削除する。
- 通常日20問を6日、復習日50問を1日保存しても、ブラウザ保存容量に十分収まるデータ量に限定する。
- 体験会も結果再表示の対象にする。
- 満点で誤答がない場合も、当日の結果画面を再表示できるよう保存する。
- ホストがルームを終了しても影響を受けない。
- 同じ端末・同じブラウザに限定し、Railwayへ参加者個人の保存結果を追加しない。
- 既存の週次誤答保存は、今回の日別結果復元とは役割を分けて維持する。

### 終了済み招待リンク

- ホスト終了後の古い招待リンクでは新規参加させない。
- URLの参加コードと同じ保存結果が端末にあれば、サーバーのルームが削除済みでも当日の結果画面を復元する。
- 保存結果がない、期限切れ、または別端末の場合は「この回は終了しました」と表示する。
- 新しい招待リンクの参加コードに保存結果がない場合は、通常どおり名前入力・参加へ進む。

## 画面文言

- `← ゲーム選択に戻る` → `← ホームに戻る`
- 参加者結果画面の`ルームを退出する` → ボタン自体を削除
- 終了済みリンク → `この回は終了しました`
- 保存成功 → `この結果と復習内容は、このブラウザに7日間保存されます`
- 保存失敗 → `この画面を閉じると結果を復元できません`

## データと費用

- 認証用に追加のデータベースや有料サービスは使わない。
- 認証はRailway環境変数と署名付きCookieで完結する。
- 日別結果と復習は各参加者のブラウザに保存するため、Railwayの保存容量を増やさない。

## テスト

### 認証

- 未認証では運営用画面を使用できない。
- 正しい共有パスワードでログインできる。
- 未認証ホームでは開催ボタンが表示されない。
- 認証済みホームだけに「開催画面を開く」が表示される。
- 認証済み運営者はホームからパスワード再入力なしで開催画面へ進める。
- 誤ったパスワードを拒否し、規定回数で一時制限される。
- Cookieに必要な属性が付く。
- 未認証Socketはルーム作成と全ホスト操作を拒否される。
- 認証済みSocketは3コースのルームを作成・進行・終了できる。
- パスワード未設定時は運営機能を閉じる。

### 参加者導線

- 結果画面に参加者用の「退出」が表示されない。
- 結果画面に参加者用の「ホームに戻る」が表示されない。
- 結果発表後、同じ画面内で解き直しと結果確認を往復できる。
- ホスト終了後も表示中の結果確認と解き直しを継続できる。
- 画面を閉じた後、同じ招待リンクから当日の結果と復習を再開できる。
- Day 1とDay 2など複数日の結果が、異なる参加コードで混ざらず復元される。
- 新しい日の招待リンクは新しい参加画面を表示する。
- 結果から7日後は保存結果を削除し、古いリンクでは終了済み案内を表示する。
- 別端末、保存領域なし、破損データでは安全に終了済み案内へフォールバックする。
- 通常の参加、途中入室、回答復帰、提出、結果発表は従来どおり動作する。
- 100人想定の負荷テストを再実行する。

## 本番反映

GitHubのレビュー済みPRを`main`へマージし、Railwayの自動デプロイを使う。デプロイ後に、本番URLで未認証拒否、事前ログイン、ルーム作成、参加、結果発表、ホスト終了、同じ招待リンクからの結果・復習再開、翌日の別コード参加を確認する。
