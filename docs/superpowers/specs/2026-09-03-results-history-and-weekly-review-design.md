# 日別結果履歴・今週の間違い復習 改修設計

## 目的

毎日19時30分に実施するClacel・TOEIC・IELTSの単語テストについて、運営者が日別の参加人数と満点者を後から確認でき、参加者が同じ端末・同じブラウザで今週間違えた問題を復習できるようにする。あわせて、結果画面・参加ロビー・提出確認・解き直し画面に残る表示不整合を修正する。

## 確定要件

- 利用者は3コース合計で約100人を想定する。
- 各コースの開催は1日1回、開始時刻は毎日19時30分（Asia/Tokyo）とする。
- 日別結果履歴は運営者専用とし、専用パスワードで保護する。
- 日別結果に保存するのは日付、コース、Day／問題セット、参加人数、満点者名のみとする。回答時間および全参加者の点数は保存しない。
- 同じ日・同じコースの結果が再度確定した場合は、古い記録を最新結果で置き換える。
- 履歴は無期限に保持し、運営者がコース単位の記録を個別削除できる。
- 参加者の復習データはサーバーへ集めず、参加者自身のブラウザにだけ保持する。
- 復習入口の表記は「今週の間違いを解く」とする。「過去6日分をまとめて解く」「正解済みを除いて再挑戦する」は設けない。
- 参加ロビーの「前回の間違い20語」は削除する。結果画面の答え合わせは残す。

## 保存構造

既存の`/data/quiz-rooms.json`をバージョン2へ拡張し、一つの原子的スナップショットに進行中ルームと結果履歴を保存する。

```json
{
  "version": 2,
  "rooms": {},
  "resultHistory": {
    "2026-09-03:clacel": {
      "date": "2026-09-03",
      "category": "clacel",
      "setLabel": "Clacel Day 3",
      "participantCount": 32,
      "perfectNames": ["Aica", "Miki"],
      "updatedAt": "2026-09-03T11:05:00.000Z"
    }
  }
}
```

- 既存バージョン1の`rooms`をそのまま読み込み、`resultHistory`が無ければ空として移行する。
- 結果発表時に、ルームの`finished`状態と日別履歴を同じ原子的書き込みで確定する。
- 保存に失敗した場合は結果発表を成功扱いせず、ルームと履歴を変更前へ戻す。
- ホストがルームを終了した際は`rooms`からのみ削除し、`resultHistory`は残す。
- 日付判定はサーバー時刻のAsia/Tokyoを使用する。
- 履歴キーを`日付:コース`とすることで、1日1コース1件を保証する。

## 運営者用の月間カレンダー

`/results-history.html`を追加する。

- 初回表示は専用パスワード入力画面とする。
- 認証成功後、当月のカレンダーを表示する。
- 開催日のセルにはClacel・TOEIC・IELTSを区別する点を表示する。
- 日付を押すと、その日の各コースについてDay／問題セット、参加人数、満点者数、満点者全員の名前を表示する。
- 未開催コースは「記録はありません」と表示する。
- 前月・次月へ移動できる。
- 各コース記録に「この記録を削除」を設け、確認後に削除する。
- 削除に失敗した場合は画面から消さず、理由を表示する。
- 回答時間、全参加者名、全参加者点数は表示・配信しない。

## 結果履歴の認証

- Railwayへ`RESULTS_ADMIN_PASSWORD`を設定し、GitHubやHTMLへ値を書かない。
- 教材編集用`ADMIN_PASSWORD`とは分離する。
- ログインAPIはパスワードをタイミング安全に比較し、成功時に有効期限12時間の署名付きHttpOnly・Secure・SameSite=Strict Cookieを設定する。
- パスワードをブラウザの`localStorage`へ保存しない。
- 履歴取得・削除APIはCookie認証を必須とし、`Cache-Control: no-store`を返す。
- ログアウトでCookieを削除する。
- 認証失敗回数をIP単位で制限し、総当たりを抑止する。
- `RESULTS_ADMIN_PASSWORD`未設定時は履歴APIを503にし、公開状態へフォールバックしない。

## みんながつまずいた単語 上位3つ

現在は参加者ごとの点数だけを保存しており、サーバーが`mistakes`を生成していない。一方、ホスト画面は空の`mistakes`を「全員正解でした」と表示するため、満点者0人と矛盾する。

修正後は提出時に生の回答文字列ではなく、誤答した問題番号だけを参加者状態へ保存する。結果発表時に問題番号ごとの誤答人数を集計し、以下の規則で上位3語を作る。

1. 誤答人数の多い順
2. 同数の場合は問題の出題順
3. 表示項目は単語、日本語の意味、誤答人数

誤答が1件もない場合は「みんながつまずいた単語 上位3つ」の見出しと一覧を両方非表示にする。「全員正解でした」という代替文言は使用しない。満点者が0人の場合は満点者欄だけに「今回、満点の人はいませんでした」と表示する。

## 提出前の問題別修正

提出内容の確認画面では、未回答・回答済みを問わず任意の問題を選択できる。

```text
提出内容の確認
  → 第7問を選択
  → 第7問だけ修正
  → 「確認一覧へ戻る」
  → 第12問を選択
```

- 確認一覧から入ったことを専用状態で記録する。
- 選択した問題では通常の「次へ」を「確認一覧へ戻る」に変える。
- 入力内容を保存して、即座に確認一覧へ戻す。
- 20問目まで順番に進み直す必要をなくす。
- 通常回答中の「戻る」「次へ」は変更しない。

## 今週の間違いを解く

参加者の結果画面で誤答した問題について、次の情報をブラウザへ保存する。

- 結果日、コース、Day／問題セット
- 正解と許容別解
- 単語の日本語の意味
- 英文
- 例文の日本語訳

生の入力回答、氏名、ルーム用セッショントークンは週間復習データへ保存しない。

### 保持期間

- プロジェクトの7日サイクルに合わせ、同じ週のDay 1からDay 7まで保持する。
- 「今週」は暦の月曜日始まりではなく、2026年9月1日19時30分（Asia/Tokyo）を最初のDay 1開始時刻とする7日単位のプロジェクト週を指す。
- 以降の各週もDay 1開始時刻をAsia/Tokyoの19時30分として週IDを算出する。
- 次週のDay 1、19時30分を過ぎたデータは読込時と保存時に自動削除する。
- 最大保持量は20問×7日×3コース=420問／端末とする。
- 通常画面では件数だけを読み、問題本文は復習開始時にだけ展開する。

### 画面とルーム終了時の動作

- 結果画面の「この単語だけ、もう一度解く」は当日の誤答だけを出す。
- クイズ入口に、保存データがある端末だけ「今週の間違いを解く（N語）」を表示する。
- 「今週の間違いを解く」は現在のプロジェクト週に保存された全問題を日付順・出題順に出す。これは唯一の週間復習入口であり、「過去6日分」という別ボタンは作らない。
- 解き直し画面では単語の意味、英文、例文の日本語訳を通常問題と同じ順序で表示する。
- ホストがルームを終了しても、結果画面または解き直し画面にいる参加者はそのまま復習を続けられる。ルーム終了は画面内メッセージで知らせる。
- 後から同じブラウザでクイズ入口を開いた場合も、期限内なら復習を再開できる。
- 期限切れ、ブラウザデータ削除、シークレットモード、別端末・別ブラウザでは復元できないことを画面に短く記載する。
- 参加ロビーには週間復習の単語一覧を表示しない。

## 費用と性能

- 新しいRailwayサービス、データベース、ボリュームは追加しない。
- 参加者の週間復習データは各端末に分散するため、100人分がRailwayへ蓄積されない。
- 運営者用履歴は1日最大3件で、既存5GBボリューム内では十分小さい。
- 保存データを必要な画面でのみ展開し、ホームおよび参加ロビーの初期描画を重くしない。
- Railwayは従量課金のためCPU・メモリ・通信の絶対的な追加料金ゼロは保証しないが、本機能のための固定費や別サービス費は発生させない。

## テストと本番確認

- バージョン1状態ファイルからの移行。
- 結果発表と履歴の同時保存、保存失敗時のロールバック。
- 同日・同コースの上書き、別コースの共存、再起動後の履歴復元。
- 履歴APIの未認証、誤パスワード、Cookie期限、削除、保存失敗。
- カレンダーの月移動、日付選択、満点者0人、未開催コース。
- 誤答人数による上位3語の順位と、誤答0件時の欄全体非表示。
- 確認一覧から各問題へ移動し、1問修正後に一覧へ戻る。
- 解き直し画面の例文日本語訳。
- 週境界19時30分の直前・ちょうど・直後での保持と削除。
- ホスト終了後の復習継続と、再読込後の週間復習再開。
- 最大420問を保存した端末で容量・表示時間を確認する。
- 主催者1人と参加者99人のローカル負荷試験で、接続、同時提出、上位3語集計、結果履歴保存、終了を確認する。
- 既存の全テストを実行し、GitHub PRの必須`test`成功後にのみRailwayへ反映する。
- 本番ではテスト専用履歴を作成して、再起動、履歴閲覧、削除、ルーム終了後の復習を確認し、テスト記録とルームを削除する。

## 対象ファイル

- `server.js`: 履歴保存、誤答集計、認証・履歴API。
- `public/quiz.html`: ロビー表示削除、問題別修正、上位3語、週間復習、日本語訳。
- `public/results-history.html`: ログイン、月間カレンダー、詳細、削除。
- `tests/`: 保存・認証・UI・週境界・100人負荷の回帰テスト。
- `DEPLOYMENT.md`: `RESULTS_ADMIN_PASSWORD`と本番確認手順。

## 対象外

- 復習データの端末間同期。
- 全参加者の点数履歴。
- 回答時間の保存。
- Google Sheets、Supabase、追加データベース。
- 正解済み単語を自動除外するモード。
- 「過去6日分をまとめて解く」という別メニュー。
- Railwayプランの自動変更。
